TMI Privacy Notice

Version: 1.1-beta (pre-release draft) · Last updated: 2026-10-25 · Effective: at first public release Publisher: Poietic Studio

TMI is a desktop app: small anime-style characters — one per AI vendor — sit in the corner of your screen, react to the AI coding tools on your computer, and keep a ledger of the tokens those tools use. This notice describes what the app reads, stores, and — only if you opt in — uploads. The same text is published on the official website and in this repository; this file's git history is the public change log of the policy.

Summary

  • Core features run on your device. No account, no API key, no network needed.
  • The app contains no telemetry, no ads and no crash reporting.
  • It reads the logs and state files your AI coding tools already write locally — never your source-code files (unless you turn on "Read your files" for cLAudE in the WeChat link, which lets her read your Desktop, Documents and Downloads; see "WeChat link").
  • It does not store or upload prompts, AI replies or command contents from your AI coding tools. (Your WeChat chats with the characters are kept on this computer while "Remember our chats" is on — see "WeChat link" — and never uploaded to us.)
  • Every optional online feature is off by default. The optional features that can go online are the leaderboard (with its project showcase), the price-table update, the update check (with the installer download), the WeChat link, the card game, mini-games, watching together and everyday talk in her place, and finished daily comics. Only the leaderboard uploads anything; it shows a consent dialog listing every field first, and turning it off requests deletion of your entry.
  • We do not sell personal data.

What the app reads locally

For the token ledger (usage is counted):

Claude Code:  ~/.claude/projects/**/*.jsonl
OpenAI Codex: ~/.codex/sessions/**/rollout-*.jsonl
Kimi Code:    ~/.kimi-code/sessions/**/wire.jsonl

Only to tell whether that AI is working right now (usage is not counted, not uploaded):

Gemini CLI:             ~/.gemini/tmp/<project>/chats/*.jsonl (or ~/.cache/.gemini/tmp/… in the macOS sandbox)
ZCode:                  ~/.zcode/cli/db/db.sqlite, ~/.zcode-beta/cli/db/db.sqlite — opened read-only
DeepSeek Harness (dsh): ~/.dsh/sessions/**/session*.jsonl[.zstd]

The reader also follows CLAUDE_CONFIG_DIR, CODEX_HOME and DSH_HOME when those tools use a custom directory. The characters recover their actions from recent sessions. Usage counting starts at the end of the logs on first use and, when a saved read position is available, resumes there on the next launch. The dashboard (a separate read-only process, which also rescans in the background about 3 minutes after launch and every 6 hours) reads the full history of the three ledger sources, locally only.

From the ledger logs the app uses token counts, timestamps, model names, session identifiers, working directories, Git branches, AI-generated session titles, log paths and message types. To animate the characters it checks recent activity once a second in memory only. It uses tool names, shell commands (to distinguish testing, committing, installing, building and reading), turn boundaries and errors. For Claude Code it tracks requests and matches tool calls with progress and results by ID within each recent session. Codex call IDs match results to concurrent tools. The desktop distinguishes file listing, text search, symbol navigation, explicit file creation, editing, change review, staging, formatting and code checks. It recognizes image inspection from the tool name or the extension of an existing file argument. When a character files notes or works on her own research, the desktop uses only the category of a call already in progress. On startup Claude Code can recover activity from up to 8 MiB at the end of a recent session. Codex replays up to 1 MiB before the saved cursor for sessions modified within the past half hour. An outstanding Codex tool can stay active for up to half an hour of silence. This replay only updates the desktop state. For ZCode it runs three read-only queries — is a turn running, which tool, which model — and never touches conversation content; for a compressed DeepSeek Harness log it only checks the file's modification time.

A whole log line, which can include prompt text or a command line, passes through memory while it is parsed. The app never writes prompts, replies or commands from those logs into its own files and never uploads them.

Anti-cheat summary. Each sync carries four numbers — how many 5-minute windows the new tokens span, the busiest window, their sum and the span — computed from the logs' own timestamps. We deliberately never upload the per-window timeline, which would show when you work and sleep. The server reconciles these numbers and runs a few fixed rules on them and on its own clock; an increase that trips a rule is held back from your public score, without notice, until an administrator reviews it. Model breakdown. It grows at the same moment and by the same amount as your total, only from usage Claude Code, Codex and Kimi Code write while the app runs; the app never digs through old logs for it. The vendor comes from the model name. Unusual model names are folded into unknown.

Project showcase. Off by default and never sent if you never turned it on. The image is re-encoded on your machine (≤512 px, ≤64 KB) and stripped of EXIF location and camera data. Never uploaded: logs or database contents, prompts, AI replies, command contents, tool names, session titles, file paths, working directories, local project folder names, Git branches, source code, per-date / per-project / per-session usage, cost estimates, or any per-window breakdown.

On · Paused · Off

  • On — syncs as above.
  • Paused — no leaderboard requests; your last entry stays.
  • Off — stops syncing and requests deletion of your row (model rows and the image go with it). A failed request is retried at each launch until the server confirms. If your anonymous session has been revoked, contact us.

What stays on the server

After Off, these remain: the anonymous account in Supabase Auth; and a score-change log — one entry per change with time, totals, increase, the four numbers, app version and any hold — readable by administrators only and kept under your anonymous ID so that earlier holds still apply if the same ID rejoins. WeChat link

Off by default; not available on Windows. The app starts and stops WeClaw (https://github.com/fastclaw-ai/weclaw, MIT), a program you install yourself; it neither ships nor modifies it. WeClaw connects to Tencent's WeChat ClawBot (iLink) service; the AIs you enable — your local claude and codex CLIs on your own plans, or DeepSeek with your own API key — answer through the app (below), under their terms. Claude and ChatGPT are not supported in mainland China or Hong Kong. On your machine the app: starts weclaw start -f when no other bridge runs and stops only the one it started; draws the QR code from weclaw login without saving it; edits only the three AI entries (pointed at their own address on the local endpoint, with a local token — not your DeepSeek key, which goes to the OS keychain), their switches and the default AI in ~/.weclaw/config.json, keeping it at 0600 — WeChat links to one character at a time, the one on your desktop, so her entry is handed to the app and the other two are switched off (kept, and switched back on if she takes the desktop); an entry you wrote yourself is moved unchanged to <name>-cli (still reachable as /claude-cli) only when you yourself turn Link WeChat on, never at start-up or when the desktop character changes; adds /opt/homebrew/bin, /usr/local/bin and the common command-line folders in your home folder that exist (~/.local/bin, nvm and similar) to WeClaw's PATH, and checks whether claude and codex can be found there without running them; checks 127.0.0.1:18011/health and the last 16 KB of ~/.weclaw/weclaw.log (which contains the first 80 characters of each message) for one "sign in again" message, in memory only; trims that log above 4 MB. Local chat endpoint: only while the link is on and at least one AI is handed to the app (DeepSeek also needs a saved key), the app listens on 127.0.0.1 (a port around 18760–18799, local token and local Host header required, at most 4 requests at once). The address decides who answers — /v1/claude/… cLAudE, /v1/codex/… CodeX, /v1/deepseek/… BlueGiantFish; plain messages go to the main character's AI, and /claude, /codex, /deepseek reach the others; each uses her own personality card and notes. Settings lets you compare the four built-in personalities locally using separate, prewritten replies to the same fictional scene. Your controls

  • Use the app with every optional online feature off; or switch any one off independently.
  • Pause or turn off the leaderboard; change or blank your name and region; turn off the showcase.
  • Turn off any "What she can do" switch; delete her own folder (workspace/, which "Reset all her memories" leaves alone) and the copies in ~/.weclaw/workspace/tokenforest/.
  • Deleting local data: if the leaderboard is on, turn it Off first and wait for the deletion to complete while online — otherwise your row stays and your machine no longer holds the credentials to remove it. Then quit, delete the data folder, and delete the TokenForest entries from Keychain Access (macOS) or Credential Manager (Windows). Uninstalling does not do this for you.
  • Contact us to remove the server-side account and score-change log, or to confirm a deletion. Never send anyone your tokens.

Changes

This product was formerly called Token Forest. The first TMI release (v0.3.0) removed the tree game: tree stage, species and per-species data are no longer uploaded; tool-call names and commands are now read in memory to animate the characters; Gemini CLI, ZCode and DeepSeek Harness are read for activity only; and the dashboard keeps a local cache refreshed in the background. The same release adds the WeChat link, with its optional "What she can do" switches (all off by default; new recipients: the sites of links you sent, Tencent for files she sends, OpenAI for picture descriptions). If a future version adds new data processing — telemetry, crash reporting, new leaderboard fields, new outbound requests — this notice and the in-app consent will be updated before that version ships, and the release notes will call it out under "Privacy or network changes".
