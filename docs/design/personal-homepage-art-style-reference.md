# 个人主页美术风格基准：雾岛山居

> 基于仓库根目录 [`example.jpg`](../../example.jpg) 的视觉拆解与再设计规则。
>
> 文档版本：v1.0 · 分析日期：2026-08-21 · 用途：个人主页、Player page、分享图与后续 AI 美术生成的统一基石。

---

## 0. 这份文档解决什么问题

这不是一句“做成治愈系国风水彩”的模糊审美描述，而是一套可以被设计师、前端工程师和图像生成模型共同执行的视觉规范。以后任何个人主页相关美术，都应先从这里确认：

- 场景应该怎样构图；
- 哪些视觉特征必须保留；
- 颜色怎样取、怎样配、怎样控制饱和度；
- 建筑、植物、水体、角色、悬崖分别怎样画；
- 如何给真实网页内容预留空间；
- 如何把参考图的绘本气质转译成可用、可读、可响应的个人主页；
- 生成图出现“太艳、太 3D、太动漫、太干净、太拥挤”等偏差时怎样修正；
- 怎样判断一张新图是否仍属于同一个美术世界。

### 0.1 使用优先级

当不同段落发生取舍时，按以下顺序决定：

1. **网页信息必须清楚、可读、可操作。** 美术不能吞掉名字、名次、项目与按钮。
2. **整体氛围必须先对。** 暖雾、低饱和、手绘、生活感比单个物件是否精确更重要。
3. **构图关系必须对。** 大留白包围岛屿、多节点生活场景、斜向视线流是风格骨架。
4. **色彩纪律必须对。** 暖中性色与植物绿占主导，蓝、红、粉只做小面积点睛。
5. **细节可以变化。** 房屋、树种、人物动作和道具可随用户内容变化，不要求逐物复刻。

### 0.2 “观察”与“推导”的区别

本文使用三个标签，防止把设计建议误当成原图事实：

- **【观察】**：可直接从 `example.jpg` 看见或量化得到。
- **【推导】**：从原图规律推导出的个人主页设计规则。
- **【建议】**：为了网页可读性、响应式、无障碍或工程落地而新增的规则。

### 0.3 最重要的复用原则

**学习关系，不复制对象。**

后续生成不需要复制同一栋房、同一座桥、同一棵粉色树或同一群白色小角色。真正要继承的是：

- 暖色雾幕如何包围一块有生活的绿色高地；
- 大地色与植物绿怎样形成主色，蓝和粉怎样少量穿插；
- 大建筑、圆屋、农田、聚会点、桥和瀑布怎样构成多个可读节点；
- 细节很多但没有视觉噪音的密度控制；
- 柔软的水彩边缘与深褐色局部线条怎样共同维持可读性；
- “有人在这里生活”的叙事感怎样替代单纯装饰。

## 1. 参考图客观档案与分析边界

### 1.1 文件事实

| 项目        | 记录                     |
| ----------- | ------------------------ |
| 文件        | `example.jpg`            |
| 格式        | JPEG / JFIF 1.01         |
| 尺寸        | 597 × 335 px             |
| 宽高比      | 约 1.782:1，接近 16:9    |
| 色彩模式    | 8-bit RGB                |
| ICC profile | 未嵌入                   |
| 透明通道    | 无                       |
| 分析假设    | 按标准网页 sRGB 解释颜色 |

### 1.2 可信与不可信的细节

**高可信：**

- 宏观构图；
- 冷暖关系；
- 主色比例；
- 节点分布；
- 俯视角度；
- 手绘、水彩与绘本气质；
- 远近层次和大面积明度关系。

**中等可信：**

- 局部线宽；
- 纸张纹理强度；
- 小角色造型；
- 建筑窗格与装饰的精确结构。

**低可信，不应机械复制：**

- 1–2 px 的微小边缘；
- JPEG 压缩造成的色块与模糊；
- 单个叶片、花朵、文字牌上的内容；
- 过度放大后看到的像素噪点。

原图分辨率较低，因此“柔软”一部分来自真实画法，一部分也可能来自缩小和 JPEG 压缩。后续高分辨率生成应保留柔和边缘，但不能故意生成糊图、脏块或压缩噪声。

## 2. 一句话美术方向

> **一座被暖雾包裹、有人安静生活的东方幻想山居：以低饱和水彩和绘本线条描绘，像一张可以慢慢探索的手绘微缩世界地图。**

### 2.1 内部风格代号

建议后续统一使用：**“雾岛山居 / Misty Garden Hamlet”**。

这个名字同时包含四个核心：

- **雾**：暖色留白、空气透视、柔和边缘；
- **岛**：被悬崖、瀑布与虚空托起的完整小世界；
- **山居**：东方山水、木屋、农田、庭院；
- **生活**：角色、作物、锅灶、桥、聚会与劳动痕迹。

### 2.2 风格 DNA 配方

以下比例是设计优先级，不是像素统计：

- 40% 东方山水田园；
- 28% 儿童绘本式水彩 / 水粉；
- 20% 轻量俯视游戏地图；
- 12% 隐居、劳作与社区生活叙事。

### 2.3 正向关键词

`东方幻想`、`山居`、`田园`、`手绘`、`水彩`、`水粉`、`绘本`、`微缩世界`、`俯视三分之四视角`、`暖雾`、`低饱和`、`纸张质感`、`自然轮廓`、`松弛`、`生活痕迹`、`宁静但不空`、`多节点探索`、`温暖`、`朴素`、`有一点童话但不幼稚`。

### 2.4 反向关键词

以下任何两项同时大量出现，通常说明已经偏离：

`赛博霓虹`、`高饱和糖果色`、`写实摄影`、`3D 渲染`、`塑料材质`、`镜面高光`、`硬边赛璐璐`、`标准二次元角色立绘`、`纯扁平矢量`、`黑色粗描边`、`极简无细节`、`宏大史诗`、`阴森废墟`、`强烈末日感`、`奢华宫殿`、`机械城市`、`锐利 UI 光效`、`大面积纯白`、`大面积纯黑`、`蓝紫渐变科技风`。

### 2.5 情绪坐标

| 维度         | 目标位置                                |
| ------------ | --------------------------------------- |
| 安静 ←→ 热闹 | 约 35%：有人活动，但没有拥挤喧闹        |
| 朴素 ←→ 华丽 | 约 25%：靠丰富生活细节，而非贵重装饰    |
| 真实 ←→ 童话 | 约 60%：现实材质与童话比例共存          |
| 平面 ←→ 立体 | 约 45%：有空间层次，但不是强透视 3D     |
| 清晰 ←→ 朦胧 | 约 55%：主体可读，边缘和远景朦胧        |
| 春夏 ←→ 秋冬 | 约 60% 偏初秋：绿色仍占主导，橙黄已出现 |
| 冷 ←→ 暖     | 约 68% 偏暖：即使蓝水与青山也被暖灰中和 |

## 3. 第一眼为什么成立：视觉重心与阅读节奏

### 3.1 主体轮廓

【观察】画面不是把风景铺满矩形，而是先形成一块不规则的“悬浮高地 / 山顶盆地”，再让米黄色雾气从四周包围它。主体轮廓大致覆盖画面宽度的 85%–90%，但边缘并不贴死画框：

- 左上与左侧有大块雾白；
- 右侧由悬崖、瀑布和桥把视线带出主体；
- 上边缘的山体断断续续，留下天空般的暖色缝隙；
- 下边缘山崖截断场景，形成“世界仍向下延伸”的想象。

这种做法比普通矩形背景更有“这是一个完整小世界”的感觉，也天然适合作为个人主页的世界观容器。

### 3.2 主要视觉节点的归一化位置

以下坐标按画面左上角为 `(0,0)`、右下角为 `(1,1)` 粗略记录，用于后续生成时复刻**节奏**而不是精确复制：

| 节点         | 大致范围                  | 视觉作用                     |
| ------------ | ------------------------- | ---------------------------- |
| 左上主屋     | x 0.17–0.42 / y 0.08–0.37 | 最大的人造物，建立生活与尺度 |
| 上部山水     | x 0.38–0.94 / y 0.00–0.43 | 提供远景、冷色与空气感       |
| 中上圆屋     | x 0.47–0.65 / y 0.22–0.49 | 用圆形打破主屋的直线结构     |
| 中央农田     | x 0.27–0.58 / y 0.31–0.64 | 建立网格秩序与劳作叙事       |
| 右中聚会点   | x 0.56–0.86 / y 0.34–0.70 | 全图细节密度与暖色集中区     |
| 下部生活带   | x 0.14–0.71 / y 0.56–1.00 | 锅灶、园地、树木构成近景节奏 |
| 右下桥与瀑布 | x 0.73–1.00 / y 0.53–1.00 | 强方向线、出口、边界与冒险感 |

### 3.3 视线流

画面可读成一条松散的反向 S / 环形路径：

1. 先被左上最大房屋吸引；
2. 沿屋前平台与农田滑向中央；
3. 经圆屋与粉色树转到上部水面；
4. 再沿右侧枯枝、聚会区和蓝绿色山石下行；
5. 最后被桥与瀑布带到右下边界；
6. 下方黄色树、锅灶与小路又把视线拉回中央。

它没有一条过于明确的“唯一主线”，因此适合承载多个主页模块。用户可以先看名字，也可以先看森林或项目，每个节点都能独立成立。

### 3.4 密度分配

【观察】细节不是平均铺满：

- **高密度区**：左上房屋、右中聚会点、下中锅灶与园地；
- **中密度区**：农田、圆屋、树群、路径；
- **低密度区**：外围雾、顶部远山、水面、局部草地。

【推导】后续页面美术采用“密—疏—密—疏”的节奏，避免整页每个模块都做成同等复杂的插画。建议一屏最多 1 个高密度叙事节点、1–2 个中密度辅助节点，并为文字留至少 30% 的平静区域。

### 3.5 留白不是空白

外围留白带有浅黄、浅灰绿和极淡山影，因此它仍属于世界，而不是透明背景或纯白边。生成时要写“warm misty negative space with faint distant mountains”，不能只写“empty background”。

## 4. 构图规则：以后怎样生成同世界的新画面

### 4.1 基础画布

| 使用场景       |             建议比例 | 主体占比 |         安静区 |
| -------------- | -------------------: | -------: | -------------: |
| 桌面 Hero      |        16:9 或 1.8:1 |  60%–72% |        28%–38% |
| 个人主页分享图 |               1.91:1 |  65%–75% | 文案安全区 30% |
| 项目卡横图     |           4:3 或 3:2 |  70%–82% |        15%–25% |
| 手机 Hero      | 4:5 或 9:16 独立重构 |  65%–75% | 上部或中部 30% |
| 方形头像场景   |                  1:1 |  75%–85% | 外圈雾 12%–18% |

### 4.2 推荐的个人主页 Hero 构图

原图中心细节较多，没有天然文字安全区，不能把名字直接压在中央农田和角色上。个人主页建议做**非对称再构图**：

```text
┌──────────────────────────────────────────────────────────────┐
│ 暖雾 / 极淡远山          │ 山脉、水面、树冠                  │
│                          │                                  │
│ 姓名 + 一句话             │ 当前主树 / 住宅 / 小角色          │
│ 名次 + 分享按钮           │                                  │
│                          │ 田地、路径、项目告示牌             │
│ 文字安全区约 36%          │ 场景主体约 64%                    │
│                          │                 悬崖 / 瀑布 / 桥   │
└──────────────────────────────────────────────────────────────┘
```

规则：

- 文字区可以有雾纹、远山和极淡植物，但不能有角色脸、房屋窗格或高对比枝条；
- 场景主体向右或向右下集中，不能居中铺满；
- 姓名区的背景明度变化控制在约 8% 以内；
- 主体不贴右边，至少留 4%–6% 呼吸空间；
- 瀑布、桥、小路等方向线不要穿过正文；
- 生成图不写任何真实文字，文字由 HTML 渲染。

### 4.3 模块化场景构图

个人主页不是每一屏都需要一张完整地图。更稳定的方式是把世界拆成“场景节点”：

| 页面内容        | 场景隐喻              | 构图建议                             |
| --------------- | --------------------- | ------------------------------------ |
| 当前身份 / Hero | 山居入口与主树        | 一大一小两个视觉锚点，旁边留文字区   |
| 两个榜单名次    | 两块山石碑 / 木牌     | 成对但不完全对称，放在路径两侧       |
| 个人森林        | 分层苗圃 / 多块种植地 | 2–4 列自然错落，不做机械棋盘         |
| 项目介绍        | 工坊、书屋或公告牌    | 一个高密度节点，图片可成为“屋内窗口” |
| 经历 / 时间线   | 蜿蜒山路              | 节点沿路径生长，不用标准竖线         |
| 技能            | 菜圃、工具架、种子袋  | 小图标像物件，不像 SaaS 徽章墙       |
| 联系 / 下载 CTA | 木桥、山门或渡口      | 作为离开 / 进入世界的动作隐喻        |
| Footer          | 悬崖下的雾与瀑布      | 逐渐降低细节，平静收尾               |

### 4.4 禁止的构图捷径

- 不把所有东西放在正中央形成一坨圆形岛；
- 不把四个模块均匀放在四角，像信息图；
- 不用完美对称宫殿式构图；
- 不让主体顶满画布、完全失去外围暖雾；
- 不只画一个漂亮房子而没有路径、活动和尺度参照；
- 不把人物排成一行看镜头；
- 不让瀑布、树枝或屋檐穿过姓名和按钮；
- 不依赖后期模糊来制造文字安全区，应在生成阶段就留出低细节区。

## 5. 透视、空间与尺度

### 5.1 视角

【观察】参考图使用高位三分之四俯视，接近等距 / 游戏地图视角，但没有严格的工程等轴网格：

- 可以同时看见屋顶、正面和侧面；
- 圆屋顶部可见，墙面仍保留足够高度；
- 地块近似平行四边形，但允许手绘变形；
- 山体、树木与建筑各自遵循局部透视，不追求单一消失点；
- 视角稳定，几乎没有广角夸张。

【推导】生成提示应优先使用：

`elevated three-quarter view`、`soft isometric-like perspective`、`storybook map view`、`no dramatic lens distortion`。

避免只写 `top-down`，否则容易得到完全垂直俯视、像策略游戏地图的结果。

### 5.2 四层空间

| 层级          | 内容                 | 清晰度 | 对比度 | 色彩倾向             |
| ------------- | -------------------- | ------ | ------ | -------------------- |
| L0 外围空气层 | 暖雾、极淡远山       | 最低   | 最低   | 奶油黄、灰米、浅灰绿 |
| L1 远景层     | 山体、瀑布源头、水面 | 偏低   | 偏低   | 灰青、蓝绿、粉灰     |
| L2 主生活层   | 房屋、农田、聚会区   | 最高   | 中高   | 黄土、植物绿、深褐线 |
| L3 前景边界层 | 悬崖、桥、近树、锅灶 | 中高   | 中高   | 赭石、橙黄、深绿     |

景深不是通过摄影式虚化制造，而是通过**对比度、色温、边缘清晰度和细节数量**共同控制。

### 5.3 尺度参照

白色小角色是最重要的尺度尺：

- 角色高度约为画面高度的 3%–5%；
- 房门约 1.2–1.5 个角色高；
- 主树高约 3–5 个角色；
- 主屋长度约 8–12 个角色；
- 桥宽约 1.5–2.5 个角色；
- 山体不追求地理真实，而是服务于微缩世界。

后续即使换成人类化 avatar，也应保持“环境大、角色小”的关系。不要把个人头像画成占半屏的大头立绘，否则会立刻从“可探索世界”变成“角色海报”。

### 5.4 深度线索

- 重叠优先于透视缩放；
- 远山减少线条，近物增加深褐局部轮廓；
- 悬崖用垂直色带表明高度；
- 瀑布跨越上下层，是最强的垂直深度线索；
- 路径用浅土色连续带串联节点；
- 水面用局部高光与环形岸线定义，不靠高饱和蓝色；
- 山脚、树根和建筑底部使用很轻的接触阴影，避免物件漂浮。

## 6. 形状语言与线条语言

### 6.1 大形状

风格建立在“软自然形 + 少量人造直线”的对比上：

- 山体、树冠、草地边缘、水岸：圆润、不规则、连续弯曲；
- 房梁、农田、桥板、告示牌：清楚但略微手抖的直线；
- 路径：宽窄变化，边界不封死；
- 屋顶：大弧面或缓斜面，避免尖锐哥特轮廓；
- 角色：胶囊形、豆形或团子形，细节非常克制。

### 6.2 轮廓线

【观察】不是所有对象都统一描边：

- 建筑、树干、角色和关键道具有较明确的深褐线；
- 草地、水面、雾与远山主要靠色块边界；
- 远景线更细、更灰、更断续；
- 近景线更深，但仍不是纯黑。

【建议】按 1920 px 宽的网页主插画计算：

- 主要建筑轮廓：2–4 px，带压力变化；
- 内部结构线：1–2.5 px；
- 角色轮廓：1.5–3 px；
- 远山线：0–1.5 px，局部消失；
- UI 线条另行控制为 1 px 或 2 px，不要模拟粗画笔。

### 6.3 线色

推荐线条色阶：

- 主轮廓：`#5B4635`；
- 最深局部：`#40352D`；
- 木结构：`#745A43`；
- 远景线：`#8F927E`；
- 水岸线：`#5D8177`；
- 暖色物件线：`#7D5842`。

绝对不要大面积使用 `#000000`。黑色会把绘本氛围切成漫画贴纸。

### 6.4 边缘节奏

一张合格插画应同时拥有：

- 20%–30% 清晰硬边：门窗、桥边、角色、关键道具；
- 45%–55% 半软边：树冠、屋顶、田块、山石；
- 20%–30% 消失边：雾、远山、草地与背景交界。

不能全糊，也不能每个对象都像剪纸一样边缘锐利。

## 7. 材质、笔触与纹理

### 7.1 核心媒介感

参考图接近“水彩打底 + 不透明水粉提形 + 彩铅 / 墨线补结构”的混合效果：

- 大地和天空有透明水彩式色层；
- 建筑与树冠有较厚、不透明的局部覆盖；
- 暗线像铅笔或稀释墨线；
- 小花、窗格、角色是最后补上的清晰点；
- 同一色块内部有轻微色相漂移，不是数字工具的纯色填充。

### 7.2 数字模拟配方

如果用数字绘画或后期合成，建议按以下顺序：

1. 暖米色纸张底色；
2. 低不透明度大水彩铺主色；
3. 用带颗粒的半干笔刷塑造山、草、屋顶；
4. 用深褐细笔补建筑结构、树干与角色轮廓；
5. 用偏黄白和偏青白点小花、水光、窗光；
6. 用暖雾色罩统一远景；
7. 最后只在 3–5 个视觉节点增加局部清晰度。

### 7.3 纹理强度

| 纹理       |          建议强度 | 说明                     |
| ---------- | ----------------: | ------------------------ |
| 纸张细颗粒 |             2%–5% | 全局可见但不能像噪点滤镜 |
| 水彩云纹   |            4%–10% | 用于雾、草地、水面       |
| 干刷破边   |       8%–18% 局部 | 只用于山石、树冠、屋顶   |
| 色彩漂移   | RGB 每通道约 3–10 | 避免大面积纯色           |
| 暗角       |             0%–5% | 参考图不靠强暗角聚焦     |
| 胶片噪点   |                0% | 不是电影摄影风           |

### 7.4 材质禁区

- 不要塑料般光滑的树叶；
- 不要 PBR 岩石、镜面水面和真实体积云；
- 不要在每个表面叠相同颗粒，形成统一脏噪；
- 不要用纸张纹理遮盖结构问题；
- 不要把水彩误解成低清晰度；
- 不要使用过强锐化和 HDR 局部对比。

## 8. 光线、阴影与空气

### 8.1 光线类型

【观察】画面接近阴天或被薄雾过滤的漫射日光：

- 没有明确太阳圆盘；
- 投影很短、很软，甚至局部省略；
- 物体主要靠固有色与接触阴影区分；
- 高光集中在水花、窗面、小白花和角色身上；
- 暖色背景让整个场景保持舒适，而不是阴冷。

### 8.2 光照规则

- 主光可默认来自左上前方，但方向感保持弱；
- 阴影色使用灰绿、灰褐或蓝灰，禁止纯黑；
- 建筑檐下可比墙面暗 15%–25%；
- 树冠内部暗部比亮部暗 12%–22%；
- 远山明度提高、饱和度降低、对比度下降；
- 最亮值留给雾、窗光、水花和角色，不要把整片草地拉到高亮。

### 8.3 时间与季节

最符合参考的默认状态：

- 时间：上午后段到午后前段；
- 天气：薄雾、无强烈直射光；
- 季节：夏末初秋；
- 温度：温暖但不炎热；
- 植物：70% 绿色，20% 黄橙，10% 粉红 / 枯枝 / 蓝绿变化。

若做夜景，不应直接变成深蓝赛博夜。夜景仍需保留暖纸色月光、窗口橙光和低饱和蓝绿，且是同一世界的夜晚，而非换了一套风格。

## 9. 元素级拆解

### 9.1 地形与悬崖

【观察】高地顶部以灰绿和苔绿色为主，悬崖侧面使用赭石、粉棕、灰青的垂直笔触。边缘并非锯齿石块，而是圆润草坡压住竖向岩壁。

生成规则：

- 顶部轮廓宽厚、圆钝；
- 侧壁用 3–5 个相邻大色带，不刻满岩石裂纹；
- 色带方向以垂直为主，少量斜线表达层理；
- 草与岩之间允许软渗色；
- 只在桥头、瀑布边和近景突出结构线；
- 悬崖颜色是“粉赭 + 灰青 + 苔绿”，不是统一棕色。

### 9.2 山石

- 轮廓像层叠软块，不是尖锐碎石；
- 以蓝绿、灰青为主，用少量暖赭连接地面；
- 远山几乎不描边；
- 近山可用 2–3 道深青弧线强调体积；
- 每组山石形状不同，但同一组内部重复相似弧线，形成节奏。

### 9.3 水面、池塘与瀑布

【观察】水并不是高饱和蓝，而是青灰、浅蓝绿和纸白混合。水面平静，只有少量白色点和弧线；瀑布较亮，成为右侧垂直视觉锚点。

规则：

- 水色至少由灰青、蓝绿、暖灰三层组成；
- 岸边让地色轻微透入水中；
- 水面高光是短线、点、薄环，不做大面积镜面反射；
- 瀑布中心偏亮青白，边缘偏灰蓝；
- 不使用电光蓝、宝石蓝；
- 瀑布的功能不仅是水，更是“页面向下继续”的视觉指引。

### 9.4 树木

参考图里树木的差异非常重要：粉色花树、橙黄树、绿色果树、深色枯枝共同制造季节与故事。

树形规则：

- 树干细而弯，使用深褐，不做写实树皮；
- 树冠由 3–7 个相互覆盖的大团块组成；
- 团块之间有空隙，让枝干偶尔露出；
- 叶色同一棵树至少有 3 个明度 / 色相层次；
- 轮廓不画成完美圆球；
- 粉色和黄色树只做视觉节点，数量少于绿树；
- 枯枝树是结构性深色线条，用于平衡画面，不承担恐怖情绪。

### 9.5 草地、花与灌木

- 草地是混合色面，不逐根画草；
- 只在路径、建筑脚、悬崖边增加短草笔触；
- 小白花以 2–4 px 的亮点成簇出现；
- 灌木使用蓝绿或深绿团块，帮助遮挡物件底部；
- 花色不超过 3 种，避免花园式彩虹；
- 地面空区必须保留，不能所有地方都铺花。

### 9.6 建筑

【观察】主屋是木框架 + 暖浅墙面 + 赭色屋顶；圆屋则使用圆锥 / 圆弧屋顶。两者形状不同，但材质和颜色相连。

规则：

- 建筑体量小而亲人，不做宏伟宫殿；
- 木梁用深褐清晰交代，墙面用暖米黄；
- 屋顶使用陶土、茅草或木瓦质感；
- 门窗数量克制，窗格略有手绘歪斜；
- 平台、台阶、门口道具表示建筑被使用；
- 建筑脚部用草、石或物件打散，不要像 3D 模型直接插在地上；
- 可以借用东方山居气质，但不要堆满明显宗教符号、灯笼、牌坊来“证明国风”。

### 9.7 农田、路径与生活设施

农田提供少量几何秩序，是自然形状中的节拍器：

- 田块为 3–8 个不完全一致的小矩形；
- 颜色在土褐、黄绿、枯黄之间变化；
- 边界可以是浅土埂，不使用黑线网格；
- 路径连接所有关键节点，但不需要完整闭环；
- 路径色比草地暖、亮度相近，避免像公路；
- 锅灶、晒台、稻草堆、石凳和工具只需点到为止。

### 9.8 小角色与动物

【观察】白色小角色造型极简，像兔子、精灵或小动物的混合体。它们承担三件事：尺度、活力、叙事。

规则：

- 角色体积小，不能抢过建筑与树；
- 形状以白色团块为主，1–3 个深色面部点；
- 站、走、围坐、劳动、看水等动作多样；
- 角色之间应有互动，不全部朝向镜头；
- 同屏 8–14 个角色已足够，移动端减少到 3–6 个；
- 可将其中一个角色替换为用户 avatar 的微缩化身，但保持同一比例和简化程度；
- 不画精细五官、复杂服装和巨大表情。

### 9.9 道具与“生活痕迹”

风格成立的重要原因不是物件精致，而是物件彼此有因果：

- 农田旁有作物、工具或劳动角色；
- 房屋前有平台、台阶与停留空间；
- 聚会点有树荫、桌面、坐席或食物；
- 水边有石头、植物或观察水面的角色；
- 桥连接两个真实可到达的地形；
- 告示牌服务于信息，而不是无意义装饰。

后续生成每个高密度节点都应先写一句“这里发生什么”，再决定放什么物件。

## 10. 叙事语言：不是风景照，而是“生活正在发生”

### 10.1 参考图的隐性故事

画面同时呈现：居住、种植、聚会、烹饪、看水、过桥、散步。没有一个动作非常戏剧化，但它们共同证明这不是摆拍景观，而是一个持续运作的小社区。

### 10.2 个人主页的叙事转译

个人主页内容应被看成用户在世界里留下的痕迹：

- 姓名：山居的主人；
- 当前主树：最醒目的生命锚点；
- 累计 token / 排名：石碑、木牌或里程标；
- 个人森林：长期投入留下的苗圃；
- 项目：用户正在建造的工坊；
- 加入日期：山居建立的时间；
- 分享：邀请别人沿桥进入；
- 下载 CTA：带走一颗种子 / 开始自己的山居。

### 10.3 每个画面都要回答的五个问题

1. 谁住在这里？
2. 他 / 她正在做什么？
3. 哪个物件代表其最重要的成果？
4. 视线下一步会去哪里？
5. 哪块区域留给真实网页信息？

若一张图只能回答“这里很好看”，仍不够像参考图。

## 11. 色彩总论

### 11.1 量化摘要

以下数据来自对 `example.jpg` 全图像素的统计，受 JPEG、缩放与未嵌入 ICC 影响，适合描述**关系**，不应当作原画母版的绝对色值：

- 全图平均 RGB：约 `#A5A686`；
- 平均 HSV：H 约 78°、S 约 29%、V 约 71%；
- 饱和度中位数：约 29.1%；
- 明度中位数：约 69.0%；
- 中间 50% 像素饱和度约落在 19.9%–37.4%；
- 中间 80% 像素饱和度约落在 12.4%–46.5%；
- 饱和度高于 50% 的像素仅约 7.1%；
- 明度高于 85% 的像素约 19.7%，主要来自雾、纸色、水光与白色角色；
- 明度低于 45% 的像素约 3.1%，深色非常克制。

这组数据说明风格的关键不是“复古滤镜”，而是：**绝大多数颜色停留在中等明度、低到中等饱和度；真正的深色和艳色都只占很小面积。**

### 11.2 色相面积分布

按 HSV 色相粗分：

| 色相范围            | 约占比 | 视觉角色               |
| ------------------- | -----: | ---------------------- |
| 低彩中性（S < 12%） |   9.2% | 雾、灰山、柔化层       |
| 红                  |   2.3% | 花、门饰、小面积提示   |
| 橙 / 土色           |  32.0% | 建筑、悬崖、路径、木材 |
| 黄 / 奶油色         |  19.4% | 雾、纸色、作物、暖光   |
| 黄绿                |  11.0% | 草地、树冠过渡         |
| 绿色                |  19.3% | 主地表、植被、山体     |
| 青色                |   4.4% | 水、冷山、阴影         |
| 蓝色                |   2.3% | 山石与水的少量冷点     |
| 紫 / 洋红           |  近 0% | 基本缺席               |

结论：暖橙黄约占 51.4%，黄绿与绿约占 30.3%，青蓝只有约 6.7%。这就是“看起来绿色很多，却仍然温暖”的原因。

## 14. 色彩管理规则

### 14.1 主色比例

建议所有新场景遵守近似的 60 / 30 / 10 结构：

- **60% 基础环境色**：暖雾、草地、灰山；
- **30% 结构色**：木屋、路径、深植被、悬崖；
- **10% 点睛色**：粉花、黄树、蓝水、白角色、红色小饰物。

10% 点睛色不是一种颜色占 10%，而是所有高辨识度颜色合计。单一亮色通常控制在 2%–4%。

### 14.2 饱和度纪律

- 画面 75% 以上区域保持 S 15%–42%；
- S > 50% 的区域目标不超过 8%；
- 最艳颜色只用于角色附近、花、门饰、作物或交互状态；
- 大面积草地不要超过约 S 40%；
- 蓝色尤其要灰化，水和山不能抢成第一视觉锚点；
- 粉色必须向灰橙或灰红偏，不用荧光粉；
- 黄色必须偏稻草、奶油或赭黄，不用柠檬黄。

### 14.3 明度纪律

- 背景暖雾：V 88%–96%；
- 主地表：V 56%–72%；
- 建筑与路径：V 62%–86%；
- 深轮廓：V 25%–45%，面积极小；
- 白色角色：用偏暖白 `#F4EED2`，不要纯白大块；
- 页面不要依赖插画里的低对比色承担正文。

### 14.4 冷暖搭配

推荐每一个冷色节点旁都放一个暖色邻居：

- 蓝绿水面旁放粉花树或暖土岸；
- 灰青山体旁放黄绿草坡；
- 冷色瀑布旁放赭色悬崖；
- 青绿树冠旁放木褐树干；
- 冷雾背景前放暖米墙或陶土屋顶。

这样冷色负责空间，暖色负责生活，画面不会变成纯冷仙境。

### 14.5 文字对比度

- 正文优先 `ui-ink` / `ui-ink-muted`，不要直接用 `art-timber` 以外的浅美术色；
- 主按钮推荐 `#4B6D5A` 背景 + `#F7F1CE` 文字；
- `#63816B` 一类中绿配纯白约 4.30:1，不满足普通小字 AA，不应作为小字号按钮组合；
- 插画上叠字时必须有稳定的暖雾 / 羊皮纸底，不使用纯文字阴影硬撑；
- 排名、token 数字等关键信息不能只靠红绿区分。

### 14.6 屏幕与文件管理

由于参考图没有 ICC profile，本文统一按 sRGB 解释。未来母版和导出遵守：

1. 网页资产工作空间使用 `sRGB IEC61966-2.1`；
2. 导出时嵌入或明确转换到 sRGB，不要只“分配”profile；
3. 不以 Display P3 作为唯一母色，否则普通屏幕会出现土色和绿色漂移；
4. 透明插画使用 PNG / WebP / AVIF，避免边缘预乘到纯黑；
5. JPEG 只用于无透明的大场景预览，并检查水彩渐变是否出现色阶断裂；
6. 不通过截图取最终色；母色从本文 token 或原始高分辨率母版取；
7. 同一批资产在至少一块标准 sRGB 屏幕和一台普通手机上复核；
8. 深色、艳色和水色是最容易漂移的三组，优先核对。

### 14.7 导出质量建议

- 桌面 Hero 母版：至少 2400 × 1350；
- 常规桌面交付：1920 × 1080；
- 2× 卡片资产：目标 CSS 尺寸的 2 倍；
- 手机 Hero 单独生成 1080 × 1600 或相近比例，不从桌面图硬裁；
- AVIF / WebP 以视觉检查为准，水彩纹理处不能成块；
- 对比原母版时检查：雾是否变灰、陶土是否变红、草地是否变荧光、蓝水是否变电蓝。

## 15. UI 转译：不要把插画直接当界面

### 15.1 分层原则

个人主页应分成三层：

1. **世界层**：山、水、雾、建筑、树、角色；
2. **叙事层**：木牌、石碑、路径、苗圃等内容隐喻；
3. **功能层**：真实 HTML 文字、链接、按钮、分享、焦点状态。

世界层可以柔软，功能层必须清晰。不要把重要信息烘焙进生成图。

### 15.2 卡片

卡片不应是冷白 SaaS 玻璃盒。推荐：

- 底色：`#EFEACC` 或 `#E3DABF`；
- 边框：`1px solid rgb(91 70 53 / 28%)`；
- 圆角：14–24 px，可轻微不对称但前端保持可维护；
- 内阴影：极弱暖色，模拟纸张厚度；
- 外阴影：`0 12px 32px rgb(73 62 47 / 10%)`，不用纯黑；
- 纹理：全局统一纸纹，不要每张卡随机纹理；
- 高亮卡可增加木牌顶部或叶片角标，而不是霓虹描边。

### 15.3 按钮

主按钮：

- 深森林绿底 + 奶油字；
- 形状接近圆角木牌或厚纸签，不做胶囊玻璃；
- hover 上移 1–2 px、颜色略深；
- active 回落，不能大幅弹跳；
- focus 使用可见的双层环或轮廓，不只改颜色。

次按钮：

- 羊皮纸底 + 深褐字 + 深褐低透明度边框；
- hover 以背景暖度和边框强度变化为主；
- 外链可以用小叶片、桥或箭头图标，不用科技感外链框。

### 15.4 排名卡

现有个人主页的“总榜 / 近 30 天”双卡可视觉化为两块并列但略错位的石碑 / 木牌：

- 一块偏暖石色，一块偏青灰石色；
- 数字必须仍是 HTML，大而清晰；
- 装饰只占卡片 15%–20%；
- 不在数字背后放高细节插画；
- “无本月名次”的破折号保持平静，不画成警告状态。

### 15.5 森林卡

- 每棵树有一块独立的种植地 / 纸卡；
- 实际树种与阶段是视觉主角；
- 八段进度可表现成 8 块石阶、8 片叶或 8 格木刻，但必须一眼能数；
- token 数放在稳定底色上；
- 多棵树错落排布，但 DOM 顺序和键盘顺序保持一致；
- 不因美术错位造成不同卡片尺寸难以比较。

### 15.6 项目卡

项目区可表现为“山居工坊 / 公告牌”：

- 项目图是视觉窗口，不套复杂画框；
- 项目名是牌面主标题；
- 描述像纸条或木板正文；
- 外链按钮像通往外界的小桥；
- 无项目时只留安静空地 / 合上的告示牌，不生成“破败废墟”负面暗示。

### 15.7 导航与页脚

- 导航尽量轻：暖雾半透明纸面或顶部细木条；
- 滚动后可变成稳定纸色，不持续遮挡景物；
- Footer 逐渐回到雾和瀑布，降低细节；
- 法律 / 隐私 / 语言等功能链接必须是标准可读链接，不伪装成画面小字。

## 16. 字体与排版

参考图几乎没有可分析的正文排版，因此本节是【建议】，目标是匹配绘本气质但不牺牲网页阅读。

### 16.1 字体角色

- 中文大标题：有温度的宋体 / 书卷感衬线，笔画不能太细；
- 中文正文：清晰现代黑体，避免整页仿宋造成阅读疲劳；
- 英文标题：人文衬线或略带手工感的 serif；
- 英文正文：低几何感 sans-serif；
- 数字 / 排名：可使用易读、略窄的数字字体，但不要终端等宽科技风；
- 手写体只用于极短装饰词，不能承担姓名、按钮或正文。

### 16.2 推荐气质

可选择类似以下方向的开源字体组合，最终使用前确认字重与语言覆盖：

- 中文标题：Noto Serif SC / 思源宋体；
- 中文正文：Noto Sans SC / 思源黑体；
- 日文：Noto Serif JP + Noto Sans JP；
- 韩文：Noto Serif KR + Noto Sans KR；
- 拉丁：与 Noto 系列统一，或使用温和的人文 serif + sans 组合。

### 16.3 排版比例

- Hero 姓名：桌面 48–72 px，手机 34–48 px；
- 一句话介绍：桌面 18–22 px，行高 1.5；
- Section 标题：32–48 px；
- 正文：16–18 px，行高 1.65–1.8；
- 辅助文字：14–15 px，不低于 13 px；
- 数据数字：36–56 px，标签与数字有明确层级；
- 行长：中文 24–34 字，英文 55–72 characters。

### 16.4 文字色

- 标题：`#3E332B`；
- 正文：`#4F443A` 或 `#3E332B`；
- 次要：`#6E6252`；
- 链接：`#345B49`，同时保留下划线或形状提示；
- 不用浅橄榄绿写正文；
- 不在繁忙树叶、水面或木纹上直接放长文。

## 17. 图标与微型插画

### 17.1 图标风格

- 1.5–2 px 深褐线；
- 圆角转折；
- 只用 1 个主色 + 1 个浅色填充；
- 轻微手绘偏差，但按钮点击区域保持规则；
- 图标对象优先来自世界：叶片、种子、桥、木牌、星点、水滴、工具、篮子；
- 不使用霓虹线性图标、玻璃拟物或金属高光。

### 17.2 头像 / 用户化身

若需要生成用户化身，推荐两种模式：

1. **小居民模式**：把人物简化为 2–2.5 头身的小角色，服装只保留 2–3 个身份特征；
2. **白色守林灵模式**：保持参考图的白色极简角色，通过围巾、帽子、工具或颜色点表达个性。

不要同时追求真实肖像相似度和极简小角色风格。需要高相似度时，应把真实头像放进项目 / 身份卡，而不是强塞进世界层。

## 18. 与现有 Token-Forest 像素资产的关系

参考图是柔和手绘绘本，不是像素画；现有树与部分产品视觉则是像素资产。两者混用必须有明确规则。

### 18.1 推荐：分层混合，而不是直接混画

- 环境背景使用“雾岛山居”手绘风；
- 真实树 sprite 保持原始像素，不用 AI 重画来伪装一致；
- sprite 放在羊皮纸卡、苗圃格或木牌框内，让媒介差异成为“收藏物 / 游戏物件”的刻意层次；
- 两套视觉通过共同的土黄、植物绿、深褐轮廓连接；
- 像素 sprite 使用 nearest-neighbor 缩放，不能被浏览器柔化；
- 手绘背景降低局部对比，避免与像素树竞争。

### 18.2 不推荐

- 把清晰像素树直接贴在柔软草地中央，没有底座或框架；
- 对 sprite 加水彩滤镜、模糊或 AI 重绘，导致树种阶段不准确；
- 让 UI 一半像素硬边、一半玻璃拟态；
- 为“统一”而把整页重新做成像素画，这会丢失本参考的核心价值。

### 18.3 如果未来决定完全手绘化

必须先建立每个树种 8 阶段的统一转绘规范，并验证阶段可辨识性。没有完整树种系统前，不应只重画 Hero 的一棵树，造成页面内同一对象两套画法。

## 19. 响应式规则

### 19.1 桌面

- 视觉主体与文字可左右分区；
- Hero 保留完整悬崖 / 瀑布方向线；
- 多节点景观可出现 6–8 个兴趣点；
- 角色 8–14 个；
- 最小文字安全区 34% 宽；
- 页面正文最大宽度约 1180–1280 px。

### 19.2 平板

- 主体缩至 4–6 个兴趣点；
- 删除最小道具，不只是等比缩小；
- Hero 文字区与插画区可以 45 / 55；
- 两张排名卡仍并排，森林卡 2–3 列；
- 边缘雾至少保留 8%。

### 19.3 手机

手机必须独立重构，不从桌面 16:9 图中间裁切：

- 画面改成纵向“山路向下”结构；
- 上部是暖雾和姓名；
- 中部是主树 / 主屋；
- 下部沿路径进入排名、森林、项目；
- 角色减少到 3–6 个；
- 桥 / 瀑布可改成垂直贯穿的滚动线索；
- 移除远处小屋、次要山石和过小花点；
- 不让插画背景导致正文每一行的对比度变化。

### 19.4 小屏简化优先级

保留顺序：

1. 用户身份和主树；
2. 一条路径 / 方向线；
3. 一个建筑或项目节点；
4. 一组代表性植被；
5. 少量角色；
6. 次要道具；
7. 远景山群。

空间不足时从列表底部开始删，不要先删主树和路径。

## 20. 动效语言

参考图本身是静态的。动效是网页适配，必须像“世界在呼吸”，不能像营销落地页在表演。

### 20.1 动效层级

| 层级     | 对象                      | 建议                        |
| -------- | ------------------------- | --------------------------- |
| 环境呼吸 | 雾、水光、少量树叶        | 8–20 秒缓慢循环             |
| 生活动作 | 角色停顿、转身、走 2–6 px | 4–10 秒，不同步             |
| 导航反馈 | 按钮、卡片、链接          | 120–220 ms                  |
| 滚动层次 | 远山、主体、前景          | 轻微视差，差值 4–18 px      |
| 重点揭示 | 姓名、主树、项目          | 淡入 + 小幅上移，不缩放弹跳 |

### 20.2 运动曲线

- 环境：`ease-in-out` 或近似正弦；
- 进入：柔和 decelerate；
- 按钮：短促但不弹簧；
- 角色：有停顿，不做机械匀速循环；
- 水：相位错开的微弱亮度变化，不做真实流体模拟。

### 20.3 幅度限制

- 树叶摆动：1°–2.5°；
- 雾位移：8–24 px / 12–20 秒；
- 角色呼吸：1–2 px；
- 卡片 hover：上移 2–4 px；
- 视差：移动端关闭或减半；
- 任何装饰动画都不能改变布局或妨碍点击。

### 20.4 Reduced motion

`prefers-reduced-motion: reduce` 时：

- 停止循环摆动、雾移动和视差；
- 保留即时颜色 / 边框反馈；
- 内容仍完整可见；
- 不把关键状态绑定到动画结束。

## 21. 资产分层与生产方式

### 21.1 推荐分层

为了响应式和轻动效，一张完整场景建议至少拆为：

1. `mist-back`：最远暖雾与淡山；
2. `mountain-back`：远山与远瀑；
3. `island-base`：主地形与悬崖；
4. `water`：池塘、河道、瀑布亮层；
5. `buildings`：房屋、桥、告示牌；
6. `vegetation-back`：大树与后层灌木；
7. `vegetation-front`：前层草花与遮挡；
8. `characters`：角色 / 动物；
9. `atmosphere-front`：薄雾、花瓣、水光；
10. `html-content`：真实文字与功能控件，不进入位图。

### 21.2 分层边缘

- 每层透明边缘要保留 2–4 px 柔软过渡；
- 不用白底抠图再 multiply；
- 需要覆盖关系的草、脚部、角色分开处理；
- 角色脚下的接触阴影可放角色层，避免漂浮；

## 24. 生成与筛选工作流

### 24.1 Round 0：先定结构，不追细节

生成 4–8 张低成本构图草案，只看：

- 主体轮廓是否像完整小世界；
- 文字安全区是否真的平静；
- 视线是否从身份区流向主树、森林和项目；
- 桥 / 瀑布 / 路径是否帮助浏览方向；
- 画面是否存在至少两个疏密变化。

此轮不要因为某棵树漂亮就选构图失败的图。

### 24.2 Round 1：锁色

从最好的 2 个构图各出 3 个色彩变体，检查：

- 暖橙黄约占一半；
- 植物绿约占三成；
- 青蓝是否仍然小于一成；
- 高饱和区域是否被控制；
- 外围雾是否偏黄而不是灰白；
- 陶土是否偏柔和而不是红砖橙。

### 24.3 Round 2：锁媒介

只调整：

- 水彩透明层；
- 水粉实体感；
- 深褐线条强度；
- 纸张纹理；
- 远近边缘。

若这一步仍像 3D 模型，不要用纸纹遮盖，回到媒介提示重做。

### 24.4 Round 3：生活叙事

为每个高密度节点写一句动作，再补角色与道具。例如：

- “两位居民在主树下整理收获”；
- “一个居民站在桥头看瀑布”；
- “两位居民在工坊门口讨论项目”；
- “一位居民在农田边浇水”。

动作必须互不重复，且不全部面向镜头。

### 24.5 Round 4：网页合成测试

把真实姓名、最长语言文案、排名数字、分享按钮叠上去测试。至少检查：

- 中文 8–12 字姓名；
- 英文 24 字符长姓名；
- 日文 / 韩文换行；
- 四位数名次；
- 大 token 数；
- 无项目与有项目两种状态；
- 360 px 宽手机。

只有合成后仍可读的图才算通过。

### 24.6 Round 5：最终输出

- 清理伪文字与错误字符；
- 修复多余手指、重复角色、断桥、悬空房屋；
- 保持主树物种与阶段正确；
- 输出桌面 / 手机 / 分享图独立裁切；
- 转换 sRGB；
- 压缩后复核颜色和水彩纹理；
- 记录 prompt、seed / reference、版本与用途。

## 25. 常见失败模式与修正

| 失败表现               | 根因                        | 修正动作                                                                                    |
| ---------------------- | --------------------------- | ------------------------------------------------------------------------------------------- |
| 画面太鲜艳，像手游广告 | 模型放大了 fantasy / cute   | 加强 muted、gray olive、sparse accents；明确 S > 50% 少于 8%                                |
| 画面太灰、没有生命     | 只强调 low saturation       | 增加暖奶油亮部、黄树、粉花和白角色，但不提高全局饱和度                                      |
| 像 3D 建模截图         | 等距地图被模型理解成 3D     | 强调 watercolor + gouache + colored pencil；加入 uneven hand-painted shapes；删除 render 词 |
| 像标准日系动画背景     | 线条过干净、色块过纯        | 加纸纹、半软边、断线与色相漂移，角色进一步简化                                              |
| 像扁平矢量信息图       | 几何太规整、材质缺失        | 增加水彩叠色、手绘变形、遮挡与空气层                                                        |
| 国风符号堆砌           | 依赖灯笼、牌坊、飞檐        | 回到山水、木材、路径、农田与生活关系，减少符号                                              |
| 画面很漂亮但无法放文字 | 没有前置 safe zone          | 重新生成，不用后期大面积模糊补救                                                            |
| 文字区仍有树枝和人脸   | 安静区描述不够具体          | 明写 no branch/building/face/high-contrast detail in left 36%                               |
| 水面抢眼               | 蓝色太纯、面积太大          | 加灰绿和岸色，降低饱和度，缩小水面高光                                                      |
| 悬崖过于写实险峻       | rocky cliff 触发写实山岩    | 改用 rounded ochre watercolor cliff bands、soft miniature terrain                           |
| 角色太大太可爱         | 模型把 cute 当主角          | 明确 tiny residents, 3–5% canvas height, environment-dominant                               |
| 整体没有故事           | 只有房、树、山的名词表      | 给每个节点加入具体但安静的活动                                                              |
| 细节平均铺满           | 没有密度分区                | 指定 3 个高密度节点 + 大片 calm ground / mist                                               |
| 阴影太黑               | cinematic / dramatic 词过强 | 改为 diffused daylight、soft contact shadows、no black shadows                              |
| 远近不分               | 所有边缘同样清楚            | 明确 distant lighter/grayer/softer，foreground selective crispness                          |
| 手机裁切失去主树       | 直接裁桌面图                | 单独生成纵向构图，重新安排节点                                                              |
| 像素树贴上去很突兀     | 两种媒介无过渡              | 放入苗圃卡 / 羊皮纸框，统一色温并降低背景局部对比                                           |

## 26. 质量评分表（100 分）

每张候选图按下表评分。低于 80 分不进入网页，高于 88 分才可成为风格母版。

### 26.1 构图（25 分）

- 5 分：主体是不规则完整小世界，而非满版普通风景；
- 5 分：文字安全区真实可用；
- 5 分：有清楚的主视觉锚点；
- 5 分：至少存在两次疏密变化；
- 5 分：路径 / 桥 / 瀑布形成自然视线流。

### 26.2 色彩（20 分）

- 5 分：暖米、土色、植物绿占主导；
- 5 分：高饱和色面积受控；
- 4 分：青蓝仅作空间与水体点缀；
- 3 分：深色面积克制；
- 3 分：远景与前景色温 / 明度有差异。

### 26.3 媒介与边缘（15 分）

- 5 分：能读出水彩 + 水粉混合，而非滤镜；
- 4 分：线条深褐、局部存在；
- 3 分：同时有硬边、半软边、消失边；
- 3 分：纸纹轻微，不脏不糊。

### 26.4 世界与叙事（20 分）

- 5 分：建筑、地形和路径关系合理；
- 5 分：角色活动自然且有互动；
- 4 分：有劳动 / 居住 / 项目痕迹；
- 3 分：季节与植物变化丰富但统一；
- 3 分：整体宁静、有生活，不空也不闹。

### 26.5 网页适配（20 分）

- 5 分：真实 HTML 文字可读；
- 4 分：主按钮和焦点状态位置明确；
- 4 分：桌面与手机均有独立可用构图；
- 3 分：没有伪文字、水印和生成错误；
- 2 分：压缩后纹理和颜色稳定；
- 2 分：动画分层 / 透明边缘可用。

### 26.6 一票否决项

即使总分很高，出现以下任何一项也退回：

- 姓名或按钮必须压在高细节背景上；
- 主树种类 / 阶段错误；
- 图中出现无法清除的伪文字；
- 角色肢体或建筑结构明显错误；
- 整体呈现 3D、像素、霓虹或标准动漫海报气质；
- 手机只能靠裁掉主内容才能使用；
- 对比度不足导致真实信息不可读。

## 28. 最小执行版：只记住这 20 条

1. 这是暖雾中的微缩山居，不是普通风景背景。
2. 高位三分之四俯视，近似等距但保留手绘变形。
3. 主体是不规则高地，四周必须有暖色空气留白。
4. 细节分区，不平均铺满。
5. 至少有一条路径、桥或瀑布引导视线。
6. 大多数颜色饱和度在 20%–40%。
7. 暖橙黄约一半，绿约三成，青蓝不到一成。
8. 蓝水必须灰化，粉花和黄树只做点睛。
9. 深色很少，轮廓用深褐而非纯黑。
10. 水彩铺色、水粉提形、彩铅 / 墨线补结构。
11. 同时保留硬边、半软边和消失边。
12. 远景浅、灰、柔；近景只局部清晰。
13. 角色很小，用来表现尺度与生活，不做主角海报。
14. 每个高密度节点都必须“有人在做事”。
15. 文字安全区在生成阶段预留，不能后期硬糊。
16. 所有真实文字与按钮使用 HTML，不烘焙进图片。
17. 美术色与功能色分开，正文优先 `#3E332B`。
18. 桌面、手机、分享图分别构图，不只裁尺寸。
19. 与像素树混用时用卡片 / 苗圃做媒介分层。
20. 先选构图，再锁颜色，再锁媒介，最后才补道具。

## 30. 版本维护规则

- 新参考图带来的共同规律；
